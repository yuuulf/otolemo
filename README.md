# otolemo

Zoom / Google Meet の会議を、端末内だけで日本語文字起こしする自分用の macOS アプリ（Local Meeting Transcriber）。
自分のマイクと相手側（会議アプリの出力音声）を別々に取得し、音声・文字起こし・検索データは外部に送信しない。

## 動作環境

- macOS 27 以降（Apple シリコン）
- Swift 6.2 以降（Xcode または Command Line Tools）

## ビルドと起動

```sh
scripts/build-app.sh        # build/LocalMeetingTranscriber.app を作る（release）
open build/LocalMeetingTranscriber.app
```

マイクと音声キャプチャの権限は `.app` として起動したときに求められる。`swift run` だとターミナル側の権限で動くため、権限確認には使わない。

Command Line Tools だけの環境では SwiftUI のマクロプラグインが無く `@State` が使えないため、コードでは別名の `@ViewState` を使っている。

## 使い方

### 1. 診断（初回）

「診断」タブで、日本語（`ja-JP`）のオンデバイス認識が使えるかを確認する。

- モデルが「未導入」なら「ダウンロード」を押す。ネットワークを使うのはこの操作だけ。
- 「オフライン認識テスト」で音声ファイルを選ぶと、端末内だけで認識できるかと処理時間を確認できる。Wi-Fi をオフにして試すとよい。
- 第一候補は `SpeechTranscriber`。使えない・精度が足りない場合は `DictationTranscriber` を使う。

### 2. ライブ文字起こし

「ライブ」タブで相手側のアプリ（Zoom、Google Meet を開いているブラウザなど）とマイクを選び、「開始」を押す。
自分（マイク）と相手側（アプリの出力音声）は別々の認識セッションで文字起こしされ、会議の経過時刻順に並ぶ。

- 相手側はアプリの出力全体を取得する。複数人の声、通知音、同じブラウザの別タブの音声も含まれる。
- 一覧の ♪ は音声を再生中のアプリ。会議前でも起動中のアプリは選べ、音声が出始めた時点から取得する。
- 初回は「画面収録とシステムオーディオ録音」の許可を求められる。相手側が 30 秒以上無音なら警告を出す。
- 片方の系統が失敗しても、もう片方は続ける。失敗した系統は「再試行」でやり直せる。
- 「自分のマイク」を OFF にすると、相手側だけを文字起こしする（負荷が高いときの代替）。

- 薄い斜体の行は認識中の暫定テキストで、確定すると通常の表示に置き換わる。
- 録音中は赤い表示と経過時間が出る。参加者には録音・文字起こししていることを知らせること。
- マイクの抜き差しなどで入力が変わると、自動で再接続する。
- 遅延（平均・p95）と、処理が追いつかず捨てたバッファ数（欠落）を表示する。

### 3. 保存

- 確定した発言は、その都度 `~/Library/Application Support/LocalMeetingTranscriber/meetings.sqlite`（SQLite / WAL）に保存する。暫定テキストは保存しない。
- 録音中にアプリを終了すると、残りを確定・保存してから終わる。
- 強制終了やクラッシュで記録中のまま残った会議は、次回起動時に「中断」として最後の発言まで復元する。
- スリープから復帰すると、動いていた系統を作り直して記録を続ける（スリープ中は記録されない）。

### 4. 履歴と書き出し

「履歴」タブで、過去の会議を新しい順に一覧できる。

- 検索欄でタイトルと発言本文を部分一致で検索する（2 文字以下の日本語でも検索できる単純検索）。
- 会議を選ぶと全文を表示する。タイトルは編集して Return で保存。発言は右クリックで本文の修正・コピー・認識結果に戻すができる。修正しても認識結果は残る。
- ツールバーから全文コピー、Markdown / JSON への書き出し、保存先の表示、会議の削除（確認あり）ができる。
